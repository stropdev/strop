# RFC: Short descriptive title

## Problem and observable outcome

What can an editor user do or observe today? Give the keys, command or contract and the intended difference. State the non-goals. Link the tracking issue both ways.

## Proof and test obligations

Before the design: what belongs to the pure resolver or kernel? Name any changed shipped Rust decisions, their Lean claims over the extraction, and the mutations that should break them. State what is assumed, checked against Neovim, exercised by a real host or shown by a cell grid instead.

## Decision and alternatives

Describe ownership, data flow and failure behaviour. Account for preview/execute agreement, input→render, real buffers, zero config and the supported Linux/WSL binary where relevant. Compare doing nothing and the strongest alternative.

## Compatibility and delivery

What happens to existing keys, files, sessions, traces and users? Name dependencies, independently deliverable outcomes, deterministic checks and the finish line. Track unfinished outcomes in issues, not a checklist in this file.

## Decision log and as-built notes

Record dated maintainer decisions, rationale and material amendments. Update implementation and supersession when work lands, with an issue, commit or release link. A merged draft is not acceptance.
