# RFC: Prepare project symbols and search without making the index authoritative

## Problem and observable outcome

On large projects the user still waits for `Space s` and `Space /` after the symbol cache improved repeat requests. A faster wrong row is worse than a wait: selecting it can jump to another declaration or feed the wrong match into a collection. The proposal in [#261](https://github.com/stropdev/strop/issues/261) is one bounded, in-memory inventory for the pinned local project. Prepare expensive discovery and extraction once where inputs match. Give the foreground request first call on the workers. A cold, evicted or uncertain index must still produce the ordinary answer.

The required case is **one opened directory containing any mix of projects**, including multilingual projects, several projects using the same language, markerless trees and loose files. `/workarea` needs neither Git nor setup. If discovery lacks evidence, the user may declare child roots in one optional file. Opening a child does not repin the workspace. Root-wide `Space f`, `Space /` and `Space S` retain the parent scope; folder search narrows deliberately; `Space s` remains the current document only. Support for text search does not imply an outline grammar or language server exists. Disconnected roots are outside this proposal.

The three waits have different owners at the [reviewed revision](https://github.com/stropdev/strop/tree/6a175d61ec8d16d2c7e209c3f3c1146fa8d5a0d7):

| Request | What Strop already does | Where this proposal can help |
|---|---|---|
| `Space s`, current file | [`SymbolStore`](../../crates/strop-engine/src/editor/symbols/store.rs) keeps the exact document generation, buffer revision and producer. [Warming](../../crates/strop-engine/src/editor/symbols/mod.rs) adopts matching work; a miss waits for LSP or a syntax outline. | Make the right work ready sooner; reuse identical syntax extraction on open. An index cannot make a required fresh server reply arrive sooner once dispatched. Measure server, extraction and row preparation separately. |
| `Space S` and `kind:` | [Per-path syntax declarations](../../crates/strop-picker/src/source/symbols.rs) and the [project catalog](../../crates/strop-picker/src/source/catalog.rs) have [watched-scope baselines](../../crates/strop-picker/src/source/cache.rs). Workspace symbols also merge query-generation-tagged LSP replies. File length and mtime help reuse declarations; neither identifies bytes. | Share discovery, verified shards and invalidation; don't start a second workspace-symbol service or identify a semantic symbol by its name. |
| `Space /` and `Space f` | [Selection](../../crates/strop-picker/src/source/selection.rs) streams the finder but gathers eligible paths before [content search](../../crates/strop-picker/src/source/grep.rs). Optional `kind:`/`repo:` evidence, eligible dirty ropes, and parallel disk matching follow. | Overlap enumeration and exact checking. Deliver a verified match before unrelated work finishes. A retained path list alone cannot establish a negative result. |

This revisits the explicit deferrals in [0093 §9](2026-11-10-find.md#9-deferred) and [0099 §2](2026-11-12-caching.md#2-what-is-cached-and-what-is-not); it does not supersede their ranking, symbol-source or input-latency contracts. There is a user report, not a new benchmark or a confirmed diagnosis.

## Proof and test obligations — before integration

Reuse [`cache::find`/`place`/`retire`](../../crates/strop-kernel/src/cache.rs) and their [existing theorems](../../proofs/Kernel/Cache.lean). They prove slot equality and bounds, not which source owns a path or when a project scan is complete. The following are **proposed decision contracts**, not existing theorem names. Move the decisions, not a copy, into dependency-free Rust; every eventual publisher and consumer uses them. After design acceptance, the first code slice is that pure kernel plus its extraction, Lean statements, proofs and fault calibration. No index service, persistence, worker integration or user-visible fast path lands ahead of the green proof gate.

| Decision | Claim over the extracted production decision | Mutation that must break it |
|---|---|---|
| Admit an answer for display or use | Accept implies equality of all applicable owners: root incarnation, native resource token/incarnation, content snapshot, designated producer instance/format and request generation. A match for a retired request cannot populate its successor. | Ignore the revision; omit the root generation; accept the previous server after rebind. |
| Isolate child projects | Given observed native path components and boundary records, select the deepest enclosing project, never a sibling or a string-prefix lookalike. For semantic rows require the live project/attachment generation, language and designated server to match the target's authorized binding. Identical project display names, relative suffixes and symbol names confer no authority. | Select the first enclosing parent instead of the deepest; drop the child identity on admission; admit the old attachment after a marker move. |
| Apply declarations | For arbitrary project and language IDs, declaring an in-scope boundary cannot exclude an otherwise eligible path from the underlying file/text walk. Boundary-dependent queries such as `repo:` may consume the new evidence. A language hint alone cannot turn a refused, incapable or unresolved attachment into an admitted producer. Results from an earlier declaration generation cannot settle a changed binding. | Filter the walk to declared members; treat a hinted language as an approved attachment; accept the old configuration generation. |
| Choose evidence for a path | When this surface is owned by a live buffer, a disk answer cannot win, including when the authoritative answer is empty or pending. A syntax shard cannot satisfy a semantic-server request. | Fall through to disk on zero rows, or equate syntax and LSP producers. |
| Settle a refresh | A result may discharge only the obligations captured by its own scan. Invalidations after begin survive settle; retiring a root/path or losing watch coverage cannot be undone by an old completion. | Clear a newer rescan on successful completion of an older walk; revive an entry after delete/recreate. |
| Schedule a candidate; finish a query | A hint changes priority, never eligibility. A file without verified exclusion evidence remains to be examined. `Complete` requires the requested policy/scope, exhausted authoritative enumeration, every eligible path accounted for, no pending verification and a successful, untruncated terminal result. An empty partial result proves nothing. | Turn an unknown candidate into a skip; complete on an empty queue while enumeration is open, or on cap/error. |
| Aggregate workspace coverage | A complete workspace result implies that loose eligible paths and every required child's work for **this** query have settled under the same policy/generation. A completed child cannot cover an unvisited sibling. Unsupported semantic coverage stays explicitly unavailable, not “no declarations”. Text search needs no language server. | Replace “all required” with “any”; omit loose paths; treat unsupported or pending semantic coverage as a certified empty project. |

Add each claim to [`Audit.lean`](../../proofs/Audit.lean), a named breaking mutation to [`mutants.py`](../../proofs/mutants.py), and refresh the committed extraction with `sh proofs/refresh.sh`. Where a model is needed, mutate Rust and model together. Require `docker compose --profile proofs run --build --rm proofs` to pass, including extraction drift, axiom audit and calibration, before host wiring. A proof over a hand-written second index or a mutant that only breaks a translation bridge does not count.

Use the [verified-foundation policy](2026-11-09-verified-foundation.md): **Rust → Charon → Aeneas → Lean 4** is the proof of record. Exercise job interleavings against shipped decisions with deterministic schedules. TLA+/TLC may help *find* a missed schedule (for example, a child is removed and rediscovered while its old reply is queued); replay a counterexample against Rust and retain a model only for a recorded catch. A green finite model or an unlinked TLAPS proof cannot satisfy the Lean gate.

**Trust boundary.** Equality of two integers doesn't prove that the host assigned the right bytes to either. The host must mint non-reused generations (retire/reset on exhaustion), bind payloads to the snapshot actually read, and associate LSP positions with the producing server and encoding. Filesystem enumeration is an observation over time, not an atomic snapshot; a watcher is not an oracle. The proof neither certifies the OS's notifications nor a language server's semantic analysis. Test these boundaries by reordering real events and comparing observable rows, ranges and jumps to the reference providers.

## Decision and alternatives

**One owner, not one universe of files.** Evolve the retained-scope owner in `source/cache.rs`, not a sibling database. The project inventory records native `(filesystem, root incarnation, relative PathBuf)` identities, project boundaries, observation and coverage, and optional per-file declaration shards. A shard carries its exact source identity, language, extractor/query schema and coordinate convention. A query captures its own folder, ignore/hidden and selection policy, dirty ropes, and request generation. `Space /` reopened in another directory still belongs to its captured host and scope. Discovery may share work across consumers with compatible coverage; an ignored-files query cannot borrow the completeness of the default walk.

Separate **scan scope**, **project boundary** and **server authority**. Keep one workspace walk and budget, not a full walker/pool per child. Compute child identity from the workspace incarnation and native relative components, not a basename or language. Git roots/worktrees and language markers are independent evidence: the current [catalog](../../crates/strop-picker/src/source/catalog.rs) reports a single kind per directory (`.git` takes precedence), while [warm attach](../../crates/strop-engine/src/editor/lsp/lifecycle/warm.rs) maps language markers. A Git C++ project must not lose its CMake evidence, nor may a Python marker authorize a server for its sibling. Apply existing trust/capability checks per actual attachment; when no eligible server exists, keep available syntax evidence and report its limits. Files without a recognized project still belong to the parent inventory. On a child move, removal or marker change, invalidate the affected membership and attachment before settling new results; do not drop unrelated siblings.

### Optional `.strop/workspace.toml`: boundaries, not a second LSP registry

Read one file, at the pinned **local** workspace root. Do not walk upward looking for it, merge child manifests, create it automatically or require it to open the directory. The [host adapter](https://github.com/stropdev/strop/issues/268) feeds the same inventory as discovery. Example for a checkout whose generated build metadata is not in the source tree:

```toml
version = 1

[[project]]
path = "platform/agent"
languages = ["rust", "go"]

[[project]]
path = "tools/reporter"
```

- **Paths declare project roots, not search roots.** `path` is a literal, nonempty descendant directory relative to the pinned root. No globs, URLs, absolute paths, `.`/`..`, environment expansion, or symlink traversal in the manifest or declared path. Resolve and verify containment on the host when binding the directory; a textual prefix or a one-time canonicalization is not authority for later reads. Undeclarable non-UTF-8 names remain discoverable as native names. A declaration cannot override ignore/protected-path rules. Unlisted projects and loose files remain eligible.
- **Precedence.** Add verified declared boundaries to discovered ones; identical paths mean one project, and the deepest enclosing boundary owns the file. A listed directory does not swallow a deeper discovered child. `languages` is an optional list of Strop language IDs, never a file classification or filter. At the same boundary, an explicit list replaces inferred *warm candidates* (`[]` means no speculative attach); omission keeps ordinary inference. Cold document attach still detects the actual file language. Roots and languages are many-to-many, not a switch on the fixture languages.
- **LSP association.** A warm candidate is `(workspace generation, child path, language ID)`. Use that directory as a directory, not a synthetic file in its parent; warm and cold routes must agree on the authorized attachment for that child/language. Resolve server choice, command, arguments and initialization options through the existing [languages.toml layers](2026-09-03-project-config.md), with the existing [per-project `:trust` rule](../editor.md#trust). Declaring a member neither trusts its command nor borrows a sibling's grant. Conflicting ownership is not permission to rebind a document: withhold the warm result. Unknown language ID, unavailable server or missing symbol capability: report unavailable coverage for that producer, keep other candidates, use a supported syntax outline where appropriate, and keep file/text search working. No language/server installation or startup merely from opening the manifest.
  For a markerless member without a more specific applicable project/config root, use the declared directory as the proposed `rootUri`/cwd on **both** routes. This replaces the file-directory fallback for that member, not the configuration or trust resolver. Opening an external library file still follows the [pinned-project attachment contract](2026-11-10-registers-and-pinned-project.md); it does not add that library to the workspace scan.
- **Failure and reload.** Read off the input path; v1 accepts only the keys shown. Bound the file to 64 KiB and 256 project records before scheduling validation. Reject malformed TOML, unsupported versions, unknown keys, duplicate paths or unsafe path syntax as a unit and surface one actionable diagnostic. An unavailable, ignored or no-longer-contained directory confers no boundary/attach authority. On manifest replacement, removal, watch loss or `:cd`, retire the old declaration generation before accepting new work; never keep running its queued warm requests as if current. Missing or rejected input uses ordinary discovery, not a partly applied manifest or a false empty workspace.

[VS Code](https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces#_workspace-file-schema) separates folder entries from folder settings; borrow relative paths, not the ability to add arbitrary external roots or launch settings. [Cargo's virtual workspace](https://doc.rust-lang.org/cargo/reference/workspaces.html#virtual-workspace) shows why a parent need not itself be a package; unlike Cargo, Strop must search eligible **nonmembers** too. Marker-only discovery cannot express a markerless project's intended root or distinguish multiple warm candidates reliably. A mandatory manifest would make a plain checkout less useful; embedding executable LSP configuration would duplicate an established trust boundary. Keep v1 to paths and language hints, not arbitrary metadata or a persistent index format.

**Lifecycle.** On project open, schedule a bounded background walk; publish batches from immutable inputs. Prioritize an explicit file-symbol request, exact verification of a likely hit, and current-buffer warming ahead of unopened files. Adopt identical in-flight work. Cancelling a picker detaches that consumer; no unrelated consumer loses its work. Coalesce watcher hints by native prefix; policy/ignore changes invalidate affected membership, rename retires the old identity, and overflow, dropped watch or root switch invalidates the coverage generation. A worker returns its starting generation, not the owner's generation at delivery. Publish on the event loop without waiting for a lock, walk, parse or `await` in input→render.

**Resource policy.** Start with the existing four retained scopes and 512 invalidation prefixes, the existing selection limit (100,000 paths / 16 MiB of names) and declaration bounds (4,096 files, 2 MiB/file, 64 MiB source budget). Cap retained bytes including exact-byte witnesses, queued work and outstanding deliveries separately; size those caps on the baseline before integration. One low-priority warming lane initially, bounded batches with cancellation points; do not create another full search worker pool beside the existing pool. On pressure evict unopened shards first; eviction costs work, never hides files. No startup barrier, daemon, on-disk format, new trust prompt or SSH agent.

**How a request uses the inventory:**

- **File symbols.** Keep one source per press. If the designated source is LSP, use the exact cache/request (prefetch or adopt, never flood servers with speculative opens). For syntax, a background shard can serve an opened file only if the editor can establish equality with the loaded rope and the producing grammar/query and span convention. Share extraction, not a lossy workspace row: if the shard lacks a selection or enclosing range the document provider needs, rebuild. A cheap stat or digest can select a candidate; an immutable shared snapshot or actual byte equality is the witness. Do comparisons off the input path, ideally while the bytes are already being read. After an edit use the new revision; never substitute mapped breadcrumb spans for exact picker rows. Keep the old bounded store for its actual job, not a second copy of each symbol list.
- **Workspace symbols.** Use shards for the existing syntax tier and `kind:` evidence. Keep `workspace/symbol` query ownership, coverage and deduplication in the existing router. A server reply without an exact target-disk version is not a reusable exact disk shard. Never transplant a line/column between providers. Check the target and convert the producing encoding against target text on navigation; on mismatch re-resolve or decline, don't jump to the nearest plausible token. The UTF-16 witness belongs to [#241](https://github.com/stropdev/strop/issues/241).
- **Text search and finder.** Issue a current policy-aware walk when complete membership is not established. Share one in-progress enumeration only when subscribers can see its whole eligible stream (including its beginning); otherwise enumerate independently. Feed eligible paths to the existing matcher as they arrive. Earlier candidate paths can prioritize reads, but publish only after eligibility and source bytes are checked. Search the captured dirty rope **instead of** disk for an eligible dirty path, even when that rope has zero matches. For `kind:`/`repo:` wait for necessary per-path evidence or preserve the existing three-valued contract; absence from a partial index is not a negative fact. Keep `ContentPlan` admission, byte spans, multiplicity, ranking, backpressure, exclusions and bounds. A hint-only index can improve first-hit latency; it cannot make a no-hit disk search sublinear. Search completion refers to the same observational coverage as the ordinary walk, not a claim that no concurrent write occurred.
- **Action boundary.** A verified partial row may be selectable under the existing UI rules, not proof that the search is finished. Preserve finished-only collect/review semantics and the existing stale-source write checks. Recheck the captured ticket, source and target when accepting an indexed row; if the source moved, refresh or refuse. A stale hit must never become the authority for an edit. No new key, widget, persisted preference or change to SSH (`rg` on the host) or to Vim grammar.

**Why this shape:** [Zed's project-search investigation](https://zed.dev/blog/nerd-sniped-project-search) separated first match from total time; prioritizing confirmation over scanning more candidates helped without a new database. [VS Code's search notes](https://github.com/microsoft/vscode/wiki/Search-Issues) distinguish open-editor text from ripgrep on disk and document disagreements between engines: keep Strop's source precedence and one exact admission rule. [clangd's index](https://clangd.llvm.org/design/indexing) layers a dynamic file index over a background one: adopt the precedence, not a second semantic index or clangd's persistent shards.

The cheapest alternative is to pipeline the existing walk and tune active-file production only. Choose it if it meets the measured targets without retained state. A persistent trigram index could improve repeated searches, especially misses, but an unobserved new file or same-stamp rewrite could make it skip a real hit. It also stores project-derived data and needs recovery, format migration, byte budgets and a sound candidate-superset proof for every supported query. **Not proposed for this cut.** Do not implement it, or retain whole-query answers, as a shortcut if the measured gain is insufficient.

## Compatibility and delivery

[The milestone](https://github.com/stropdev/strop/milestone/79) puts the [Lean foundation](https://github.com/stropdev/strop/issues/263) **first**. Agree the claims in review; after acceptance, pass the calibrated proof gate before [baseline and budgets](https://github.com/stropdev/strop/issues/262), host wiring or optimization. The baseline is still on the unchanged editor. Fix release build mode, workload, worker count and host; distinguish cold process, warm unchanged, one edit and overflow. Freeze p95 targets before comparing designs. Measure key→first **selectable correct** row, key→complete, input during rebuild, bytes read/parsed and peak retained memory. Include rare, common and absent terms and a slow controlled server. Keep the existing `symbols` p95 gates (10 ms kept-list paint, 5 ms input during build) and `find`/`search` gates (20/50 ms first paint/per-key, 150/400 ms first hit/complete). These are fixture budgets, not new measurements.

**Required acceptance by capability, not by language pair.** Run discovery-only and explicitly declared variants on the same tree. File and text membership must agree; changed project ownership or additional legitimate warm results are expected, not evidence that whole rows should be identical between variants. Parameterize the fixture by capabilities: several roots using one language/server kind, multiple languages under one root, a markerless declared child, syntax-only coverage, and a text-only child with neither outline nor LSP. Include an unknown hint alongside a supported one. Repeat with a different registry-backed mix (e.g. Rust and Go); changing the mix must not require changing the index algorithm or proof statements.

One concrete collision witness: open a temporary non-Git `workarea/` once. Put `team-a/service/{.git,CMakeLists.txt,src/main.cpp}` beside `team-b/service/{pyproject.toml,src/main.py}`, a nested package under the first project, and a loose `notes.txt`. Declare `render` in both source files; put the search needle in both files and the note. A matching file outside `workarea/` is the negative control. Drive the editor, not just the catalog:

- From either child, whole-workspace search returns all three eligible paths; folder search never leaks the sibling or outside file. Dirty removal of the C++ needle removes only that hit. `Space f` includes the loose file; nested ignore changes affect only the applicable paths.
- `Space S` returns both `render` declarations as distinct native targets; accept each and check the cursor. `Space s` in either file offers only its own declaration. Exercise ready, delayed and unavailable servers; inspect `initialize.rootUri`/cwd for the non-Git marker case and compare warm with cold attach. Run with the catalog capped: a known child's completion must not claim semantic coverage of the whole workspace.
- Move the nested package between siblings while its old reply is held, release the reply, and switch to a second `workspace/` with identical relative paths. Neither the previous child nor the previous workspace may publish rows in the new scope. Use an event barrier, not a sleep.
- On the markerless, multilingual variant, assert the observed server root and language for each authorized binding. Refuse an untrusted project command even when its language is listed. Replace a valid manifest with a malformed one, remove it, retarget a declared directory through a symlink, and deliver old replies. No outside path, stale jump, inherited trust or unlisted-file omission is allowed. TOML parsing, filesystem containment and actual process launch are host witnesses; Lean proves the decisions over their typed inputs, not those observations.

After maintainer acceptance and the [proof gate](https://github.com/stropdev/strop/issues/263), the [inventory owner](https://github.com/stropdev/strop/issues/264) precedes the independent [symbol](https://github.com/stropdev/strop/issues/265) and [search](https://github.com/stropdev/strop/issues/266) consumers. Compare indexed and cold paths on identical inputs: same native identities, names, ranges, match multiplicity, ranked rows and selected target on complete runs; truthful terminal state and only valid rows on capped/failed runs. Drive real buffers, headless selection/accept, cell-grid partial/empty states and temporary-tree mutations (same-length/restored-mtime rewrite, delete/recreate, nested ignore changes, invalid filenames, dirty removal of the only hit). Force overflow *during* refresh, cancel/retype, switch roots and restart the server before delayed replies. Use barriers, not sleeps. No grammar delta: keep the Neovim differential lane unchanged; Neovim is not the oracle for project search. Preserve the SSH journey and normal release gates.

Warm-root selection [#243](https://github.com/stropdev/strop/issues/243) owns the required non-Git attach witness; retain the investigation outcome even if the existing route is correct. Breadcrumb expansion [#95](https://github.com/stropdev/strop/issues/95), decoder memory [#92](https://github.com/stropdev/strop/issues/92) and zero-width row presentation [#227](https://github.com/stropdev/strop/issues/227) have different finish lines. If both reported flows cannot show a repeatable improvement without compromising correctness, return the evidence to the maintainer. Do not call a measured no-go a delivered index.
