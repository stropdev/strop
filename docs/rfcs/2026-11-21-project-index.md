# RFC: Prepare project symbols and search without making the index authoritative

## Problem and observable outcome

On large projects the user still waits for `Space s` and `Space /` after the symbol cache improved repeat requests. A faster wrong row is worse than a wait: selecting it can jump to another declaration or feed the wrong match into a collection. The proposal in [#261](https://github.com/stropdev/strop/issues/261) is one bounded, in-memory inventory for the pinned local project. Prepare expensive discovery and extraction once where inputs match. Give the foreground request first call on the workers. A cold, evicted or uncertain index must still produce the ordinary answer.

The three waits have different owners at the [reviewed revision](https://github.com/stropdev/strop/tree/6a175d61ec8d16d2c7e209c3f3c1146fa8d5a0d7):

| Request | What Strop already does | Where this proposal can help |
|---|---|---|
| `Space s`, current file | [`SymbolStore`](../../crates/strop-engine/src/editor/symbols/store.rs) keeps the exact document generation, buffer revision and producer. [Warming](../../crates/strop-engine/src/editor/symbols/mod.rs) adopts matching work; a miss waits for LSP or a syntax outline. | Make the right work ready sooner; reuse identical syntax extraction on open. An index cannot make a required fresh server reply arrive sooner once dispatched. Measure server, extraction and row preparation separately. |
| `Space S` and `kind:` | [Per-path syntax declarations](../../crates/strop-picker/src/source/symbols.rs) and the [project catalog](../../crates/strop-picker/src/source/catalog.rs) have [watched-scope baselines](../../crates/strop-picker/src/source/cache.rs). Workspace symbols also merge query-generation-tagged LSP replies. File length and mtime help reuse declarations; neither identifies bytes. | Share discovery, verified shards and invalidation; don't start a second workspace-symbol service or identify a semantic symbol by its name. |
| `Space /` and `Space f` | [Selection](../../crates/strop-picker/src/source/selection.rs) streams the finder but gathers eligible paths before [content search](../../crates/strop-picker/src/source/grep.rs). Optional `kind:`/`repo:` evidence, eligible dirty ropes, and parallel disk matching follow. | Overlap enumeration and exact checking. Deliver a verified match before unrelated work finishes. A retained path list alone cannot establish a negative result. |

This revisits the explicit deferrals in [0093 §9](2026-11-10-find.md#9-deferred) and [0099 §2](2026-11-12-caching.md#2-what-is-cached-and-what-is-not); it does not supersede their ranking, symbol-source or input-latency contracts. There is a user report, not a new benchmark or a confirmed diagnosis.

## Proof and test obligations — before integration

Reuse [`cache::find`/`place`/`retire`](../../crates/strop-kernel/src/cache.rs) and their [existing theorems](../../proofs/Kernel/Cache.lean). They prove slot equality and bounds, not which source owns a path or when a project scan is complete. The following are **proposed decision contracts**, not existing theorem names. Move the decisions, not a copy, into dependency-free Rust; every eventual publisher and consumer uses them. After design acceptance, the first code slice is that pure kernel plus its extraction, Lean statements, proofs and fault calibration. No index service, persistence, worker integration or user-visible fast path lands ahead of the green proof gate.

| Decision | Claim over the extracted production decision | Mutation that must break it |
|---|---|---|
| Admit an answer for display or use | Accept implies equality of all applicable owners: root incarnation, native resource token/incarnation, content snapshot, designated producer instance/format and request generation. A match for a retired request cannot populate its successor. | Ignore the revision; omit the root generation; accept the previous server after rebind. |
| Choose evidence for a path | When this surface is owned by a live buffer, a disk answer cannot win, including when the authoritative answer is empty or pending. A syntax shard cannot satisfy a semantic-server request. | Fall through to disk on zero rows, or equate syntax and LSP producers. |
| Settle a refresh | A result may discharge only the obligations captured by its own scan. Invalidations after begin survive settle; retiring a root/path or losing watch coverage cannot be undone by an old completion. | Clear a newer rescan on successful completion of an older walk; revive an entry after delete/recreate. |
| Schedule a candidate; finish a query | A hint changes priority, never eligibility. A file without verified exclusion evidence remains to be examined. `Complete` requires the requested policy/scope, exhausted authoritative enumeration, every eligible path accounted for, no pending verification and a successful, untruncated terminal result. An empty partial result proves nothing. | Turn an unknown candidate into a skip; complete on an empty queue while enumeration is open, or on cap/error. |

Add each claim to [`Audit.lean`](../../proofs/Audit.lean), a named breaking mutation to [`mutants.py`](../../proofs/mutants.py), and refresh the committed extraction with `sh proofs/refresh.sh`. Where a model is needed, mutate Rust and model together. Require `docker compose --profile proofs run --build --rm proofs` to pass, including extraction drift, axiom audit and calibration, before host wiring. A proof over a hand-written second index or a mutant that only breaks a translation bridge does not count.

**Trust boundary.** Equality of two integers doesn't prove that the host assigned the right bytes to either. The host must mint non-reused generations (retire/reset on exhaustion), bind payloads to the snapshot actually read, and associate LSP positions with the producing server and encoding. Filesystem enumeration is an observation over time, not an atomic snapshot; a watcher is not an oracle. The proof neither certifies the OS's notifications nor a language server's semantic analysis. Test these boundaries by reordering real events and comparing observable rows, ranges and jumps to the reference providers.

## Decision and alternatives

**One owner, not one universe of files.** Evolve the retained-scope owner in `source/cache.rs`, not a sibling database. The project inventory records native `(filesystem, root incarnation, relative PathBuf)` identities, project boundaries, observation and coverage, and optional per-file declaration shards. A shard carries its exact source identity, language, extractor/query schema and coordinate convention. A query captures its own folder, ignore/hidden and selection policy, dirty ropes, and request generation. `Space /` reopened in another directory still belongs to its captured host and scope. Discovery may share work across consumers with compatible coverage; an ignored-files query cannot borrow the completeness of the default walk.

**Lifecycle.** On project open, schedule a bounded background walk; publish batches from immutable inputs. Prioritize an explicit file-symbol request, exact verification of a likely hit, and current-buffer warming ahead of unopened files. Adopt identical in-flight work. Cancelling a picker detaches that consumer; no unrelated consumer loses its work. Coalesce watcher hints by native prefix; policy/ignore changes invalidate affected membership, rename retires the old identity, and overflow, dropped watch or root switch invalidates the coverage generation. A worker returns its starting generation, not the owner's generation at delivery. Publish on the event loop without waiting for a lock, walk, parse or `await` in input→render.

**Resource policy.** Start with the existing four retained scopes and 512 invalidation prefixes, the existing selection limit (100,000 paths / 16 MiB of names) and declaration bounds (4,096 files, 2 MiB/file, 64 MiB source budget). Cap retained bytes including exact-byte witnesses and postings, queued work and outstanding deliveries separately; size those caps on the baseline before acceptance. One low-priority warming lane initially, bounded batches with cancellation points; do not create another full search worker pool beside the existing pool. On pressure evict unopened shards first; eviction costs work, never hides files. No startup barrier, daemon, on-disk format, new trust prompt or SSH agent.

**How a request uses the inventory:**

- **File symbols.** Keep one source per press. If the designated source is LSP, use the exact cache/request (prefetch or adopt, never flood servers with speculative opens). For syntax, a background shard can serve an opened file only if the editor can establish equality with the loaded rope and the producing grammar/query and span convention. Share extraction, not a lossy workspace row: if the shard lacks a selection or enclosing range the document provider needs, rebuild. A cheap stat or digest can select a candidate; an immutable shared snapshot or actual byte equality is the witness. Do comparisons off the input path, ideally while the bytes are already being read. After an edit use the new revision; never substitute mapped breadcrumb spans for exact picker rows. Keep the old bounded store for its actual job, not a second copy of each symbol list.
- **Workspace symbols.** Use shards for the existing syntax tier and `kind:` evidence. Keep `workspace/symbol` query ownership, coverage and deduplication in the existing router. A server reply without an exact target-disk version is not a reusable exact disk shard. Never transplant a line/column between providers. Check the target and convert the producing encoding against target text on navigation; on mismatch re-resolve or decline, don't jump to the nearest plausible token. The UTF-16 witness belongs to [#241](https://github.com/stropdev/strop/issues/241).
- **Text search and finder.** Issue a current policy-aware walk when complete membership is not established. Share one in-progress enumeration only when subscribers can see its whole eligible stream (including its beginning); otherwise enumerate independently. Feed eligible paths to the existing matcher as they arrive. Earlier candidate paths can prioritize reads, but publish only after eligibility and source bytes are checked. Search the captured dirty rope **instead of** disk for an eligible dirty path, even when that rope has zero matches. For `kind:`/`repo:` wait for necessary per-path evidence or preserve the existing three-valued contract; absence from a partial index is not a negative fact. Keep `ContentPlan` admission, byte spans, multiplicity, ranking, backpressure, exclusions and bounds. A hint-only index can improve first-hit latency; it cannot make a no-hit disk search sublinear. Search completion refers to the same observational coverage as the ordinary walk, not a claim that no concurrent write occurred.
- **Action boundary.** A verified partial row may be selectable under the existing UI rules, not proof that the search is finished. Preserve finished-only collect/review semantics and the existing stale-source write checks. Recheck the captured ticket, source and target when accepting an indexed row; if the source moved, refresh or refuse. A stale hit must never become the authority for an edit. No new key, widget, persisted preference or change to SSH (`rg` on the host) or to Vim grammar.

**Why this shape:** [Zed's project-search investigation](https://zed.dev/blog/nerd-sniped-project-search) separated first match from total time; prioritizing confirmation over scanning more candidates helped without a new database. [VS Code's search notes](https://github.com/microsoft/vscode/wiki/Search-Issues) distinguish open-editor text from ripgrep on disk and document disagreements between engines: keep Strop's source precedence and one exact admission rule. [clangd's index](https://clangd.llvm.org/design/indexing) layers a dynamic file index over a background one: adopt the precedence, not a second semantic index or clangd's persistent shards.

The cheapest alternative is to pipeline the existing walk and tune active-file production only. Choose it if it meets the measured targets without retained state. A persistent trigram index could improve repeated searches, especially misses, but an unobserved new file or same-stamp rewrite could make it skip a real hit. It also stores project-derived data and needs recovery, format migration, byte budgets and a sound candidate-superset proof for every supported query. **Not proposed for this cut.** Do not implement it, or retain whole-query answers, as a shortcut if the measured gain is insufficient.

## Compatibility and delivery

[The milestone](https://github.com/stropdev/strop/milestone/79) owns pickup order. [Baseline and budgets](https://github.com/stropdev/strop/issues/262) first: same release build mode, pinned workload, worker count and host; distinguish cold process, warm unchanged, one edit and overflow. Freeze p95 targets and tolerances before comparing designs. Measure key→first **selectable correct** row, key→complete, input during rebuild, bytes read/parsed and peak retained memory. Include rare, common and absent terms and a slow controlled server. Keep the existing `symbols` p95 gates (10 ms kept-list paint, 5 ms input during build) and `find`/`search` gates (20/50 ms first paint/per-key, 150/400 ms first hit/complete). These are existing fixture budgets, **not** measurements on the reported project. Reaching them on the old small fixture alone is not a win.

After maintainer acceptance and the [proof gate](https://github.com/stropdev/strop/issues/263), the [inventory owner](https://github.com/stropdev/strop/issues/264) precedes the independent [symbol](https://github.com/stropdev/strop/issues/265) and [search](https://github.com/stropdev/strop/issues/266) consumers. Compare indexed and cold paths on identical inputs: same native identities, names, ranges, match multiplicity, ranked rows and selected target on complete runs; truthful terminal state and only valid rows on capped/failed runs. Drive real buffers, headless selection/accept, cell-grid partial/empty states and temporary-tree mutations (same-length/restored-mtime rewrite, delete/recreate, nested ignore changes, invalid filenames, dirty removal of the only hit). Force overflow *during* refresh, cancel/retype, switch roots and restart the server before delayed replies. Use barriers, not sleeps. No grammar delta: keep the Neovim differential lane unchanged; Neovim is not the oracle for project search. Preserve the SSH journey and normal release gates.

Warm-root selection [#243](https://github.com/stropdev/strop/issues/243) remains a separate investigation unless warm attach changes. Breadcrumb expansion [#95](https://github.com/stropdev/strop/issues/95), decoder memory [#92](https://github.com/stropdev/strop/issues/92) and zero-width row presentation [#227](https://github.com/stropdev/strop/issues/227) have different finish lines. If both reported flows cannot show a repeatable improvement without compromising correctness, return the evidence to the maintainer. Do not call a measured no-go a delivered index.
