# 0096 — Git: status, commit, branches (release 0.62)

Source: plan 0091 §4.7 ("Missing: status … Staging hunks without being able to
commit is half a loop") and its roadmap entry "0.60 — git" (now 0.62). This plan
closes the loop: see what changed, stage it, commit it, switch branch — without
leaving the editor and without a new kind of widget.

## 1. Research notes

What the tools people already have in their fingers do, and what we take.

- **vim-fugitive** (`:Git` summary buffer; `:help fugitive-maps`,
  <https://github.com/tpope/vim-fugitive/blob/master/doc/fugitive.txt>). A plain
  buffer: `Head:` line, then `Untracked` / `Unstaged` / `Staged` sections of
  `X path` rows. `s` stage, `u` unstage, `-` toggle, `=` toggle the inline diff,
  `X` discard, `<CR>` open, `cc` commit, `ca` amend, `]c`/`[c` hunks, and the
  maps act on the file, hunk or whole section under the cursor. The commit
  message is edited in `.git/COMMIT_EDITMSG`, a real file buffer; writing and
  closing it commits, an empty message aborts. **We take the keys and the
  commit-message-is-a-file model whole** — it is the vim-world muscle memory the
  owner asked for.
- **Magit** (<https://magit.vc/manual/magit/Status-Sections.html>) and
  **Neogit** (<https://github.com/NeogitOrg/neogit>): the same sections with a
  count in each heading (`Unstaged changes (2)`), inline hunks expanded under
  the file with `TAB`, staging at the granularity of the thing under point. We
  take the counted headings and "act on what the cursor is on". We do not take
  the transient popup menus: strop's which-key card already shows the `Space g`
  family, and a second menu system is a second UI.
- **lazygit** (<https://github.com/jesseduffield/lazygit>): files panel with
  `space` to toggle staged, `d` discard behind a confirmation, branches panel
  with `space` checkout and `n` new branch. We take the confirmation before a
  destructive discard and "git decides, we show its message" for checkouts
  (lazygit surfaces git's own error when a checkout would overwrite changes).
- **gitsigns.nvim** (<https://github.com/lewis6991/gitsigns.nvim>): in-file
  hunk verbs `stage_hunk`, `undo_stage_hunk`, `reset_hunk`, `preview_hunk`;
  `]c`/`[c`. strop's in-file verbs were `Space g s` / `S` / `u` / `p`, with `u`
  meaning *discard*. That collides with the status buffer, where `u` is
  *unstage*. One family means one meaning per letter (§2.5).
- **VS Code / Zed** put Staged above Changes above Untracked. fugitive puts
  Untracked first. We follow the owner's order (Conflicts, Staged, Unstaged,
  Untracked): what the next commit holds reads first.

## 2. Design

### 2.1 The status buffer — `Space g g`

A `Surface::Status` document: a real read-only buffer like the log and the diff.
Motions, `/`, yank and counts work because nothing special-cases them.

```
Head: main
Upstream: origin/main, ahead 1

Staged (1)
A docs/notes.md

Unstaged (2)
M src/lib.rs
@@ -1,3 +1,4 @@
 fn a() {}
+fn b() {}
 fn c() {}
M src/main.rs

Untracked (1)
? scratch.txt
```

- The buffer text is exactly what is painted: a status letter, a space, the
  repo-relative path; diff rows keep their `+`/`-`/space prefix so a yank is a
  patch and `/^+` finds additions. Colour comes from the typed row model
  (`StatusRow`), never from sniffing the text. File names follow 0088 §2 through
  `render/file_name.rs`. No chips, one accent (the branch name), greys for the
  rest, and the existing diff add/delete colours for diff rows.
- Keys act on the row under the cursor: a **file** row is the file, a **hunk**
  row (header or line) is that hunk, a **section heading** is every file in the
  section.

| key | does |
|---|---|
| `enter` | open the file (at the line, from a diff row); an untracked directory browses |
| `s` | stage |
| `u` | unstage |
| `-` | toggle: stage what is unstaged, unstage what is staged |
| `=` | expand / collapse the file's inline diff |
| `]c` `[c` | next / previous hunk (falls to the next file row when nothing is expanded) |
| `X` | discard, after `y` confirms |
| `cc` | commit |
| `ca` | amend |
| `q` | close |

- `X` on an unstaged file restores it from the index; on an untracked path it
  deletes it; on an unstaged hunk it reverts that hunk in the working file. On a
  staged or conflicted row it refuses ("unstage first"): one key never throws
  away two layers of work.
- Data: `Repo::status()` (libgit2 `git_status_list`, no index refresh, untracked
  directories collapsed as git does) on a worker. Inline diffs are
  byte-level `index↔worktree` / `HEAD↔index` hunks from the same libgit2 patch
  builder the gutter and hunk preview use; binary content says "binary".
  Renames show as a delete and an add (rename detection is deferred — path-level
  staging of half a rename needs its own design).
- Refresh: after every mutation, on file-watcher hints, when the terminal
  regains focus, and when `Space g g` is pressed again. One request per status
  document; hints that arrive mid-flight coalesce into one follow-up. The cursor
  stays on the same file/hunk when it still exists, else on the same row.
- Mutations go through the existing FIFO mutation queue, extended with
  file-level and discard operations: index and working-tree writes stay
  strictly serial and off the input path. A discard then reloads the open
  buffers on the files it rewrote (clean ones; dirty ones are marked changed
  on disk), the same treatment a watcher hint gives.
- The editor's own protocol files (`.strop-lock-*`, save and filesystem
  stages) sit beside open files. They are filtered out of every snapshot
  (`strop_fs::is_protocol_path`): never listed, never staged by a heading,
  never counted in the commit summary.

### 2.2 Commit — `Space g c`, `cc`; amend `ca`

- The message is edited in `<gitdir>/COMMIT_EDITMSG`, opened as an ordinary file
  buffer — everything is a real buffer, and this one is literally a file. A
  worker writes the template first: an empty line (or HEAD's message for
  amend), then `#` comment lines with the branch and the staged change list.
- `:wq` (or `:w` then `:q`) commits; `:q!` with no write aborts. Closing the
  buffer is the trigger, exactly as fugitive does.
- **Decision: the commit itself runs the `git` CLI**, `git commit
  --cleanup=strip -F <file> [--amend]`, as a job through `GitExec` — not
  libgit2. Reason: hooks (pre-commit, commit-msg), signing (`commit.gpgsign`),
  `user.*`, templates and `core.commentChar`-adjacent behaviour belong to git
  and its config; reimplementing them in-process would be a second, wrong git.
  It is one process per commit, off the input path, so the "no per-keystroke
  spawn" rule is untouched. The run gets a ten-minute deadline (hooks run
  linters). stdin is null: a signing setup that needs a TTY pinentry fails with
  git's own message, which we show.
- Nothing staged and not amending: refused before a buffer opens. An empty
  message: git refuses, we show its line.
- Result: git's summary line (`[main 1a2b3c4] subject`) in the echo row; status
  buffers and the gutter refresh.

### 2.3 Branches — `Space g b`

- The one picker, kind `Branches`: local branches (current first, marked
  `— current`), then remote-tracking branches, each group most-recent first.
  Listed by libgit2 on a worker.
- `enter` runs `git switch <name>` (a remote row switches to its short name, so
  git creates the tracking branch or reuses the local one). **Git decides**
  whether the working tree allows it; its refusal is shown verbatim.
- A pinned last row, "create branch from the typed name", runs `git switch -c
  <query>`. Git validates the name.
- After a switch the working tree changed under every buffer: clean buffers
  reload through the guarded watcher path, dirty ones gain external-change
  state (never clobbered), the git context is rediscovered.

### 2.4 Remote (SSH) projects — deferred

Status needs index reads and writes on the host; the remote backend is
read-oriented (0036 RW4/RW8: "no remote index write"). Doing it properly means
`git status --porcelain=v2 -z` and `git apply --cached` over the exec channel
plus reloading remote buffers after a switch, none of which is a small change.
All three commands refuse on a remote repository with one sentence ("git
status/commit/branches need a local repository") and touch nothing local.

### 2.5 One family

| where | stage | unstage | discard | preview |
|---|---|---|---|---|
| status buffer | `s` | `u` | `X` | `=` |
| in a file | `Space g s` | `Space g u` | `Space g X` | `Space g p` |

- `Space g u` was "restore hunk"; it is now unstage, and restore moves to
  `Space g X`. `Space g S` is gone. No aliases (alpha).
- `Space g b` is branches; the blame gutter moves to `Space g B`.
- Buffer titles: `git status`, `git log`, `git log ·file`, `git log ·lines`,
  `git files`, `git diff`, `git hunk`.

## 3. Structure

- `strop-git/src/status.rs` — `WorkingTree`, `StatusEntry`, `Section`,
  `FileDelta`, `Branch`; `Repo::{status, file_delta, stage_path, unstage_path,
  discard_path, discard_hunk, branches, commit_template}`.
- `strop-git/src/exec.rs` — `GitExec::run_within` (caller deadline).
- `strop-engine/src/editor/git_work/` — one owned component, `GitWork`:
  - `mod` — state (the mutation queue and every request's ownership), open,
    refresh, publish, and the one method that carries a key's decision out;
  - `rows` — pure: the buffer text and its typed row model, built together;
  - `keys` — pure: key + view + cursor line → an `Action` as data (AGENTS:
    "compute typed owners as data");
  - `anchor` — pure: where the cursor was, in terms that survive a rebuild;
  - `porcelain` — the flows that end in a `git` CLI run: commit and branches.
- `strop-engine/src/editor/git_memory/` — `MutationOp` gains the file-level
  and discard operations and its own `apply`; the queue's two methods stay in
  `jobs.rs`.
- `strop/src/render/diff/status.rs` — row decoration.

The `Editor` ratchets (0087 A4) hold: the mutation queue's two fields moved
into `GitWork`, so `Editor` has one field fewer (110), and `git_memory`'s
three `impl Editor` blocks became one (the `open_log_pub` table shim is
deleted), which pays for the component's two.

## 4. Tests

- `strop-git`: status sections for every state (staged/unstaged/both/untracked/
  deleted/conflict/unborn HEAD), stage/unstage/discard round trips against the
  `git` CLI's view, hunk discard byte-precision, branch listing order.
- Engine: the status buffer's text; every key (`s`, `u`, `-`, `=`, `X`+confirm,
  `]c`, `enter`, section headings); refresh keeps the cursor; commit and amend
  through the real `git`; aborted and empty commits; hook failure surfaces;
  branch switch, dirty-tree refusal with git's message, create from query;
  remote refusal.
- Goldens (hone/vellum × 140×40/80×24): `git-status`, `git-commit`,
  `git-branches`.
- Journey on the real binary in a PTY (`tests/terminal_editor/git.rs`): edit two
  files, `Space g g`, stage one file and one hunk of the other, `cc`, write the
  message, `:wq`; `git log -1 --stat` names both files with the staged counts
  and the unstaged hunk is still in the working tree.
- `?`: every new key has a row; the keymap coverage tests pin both directions.

## 5. Deferred

- Remote (SSH) status/commit/branches (§2.4).
- Rename detection in the status list.
- Stash, push/pull/fetch, merge/rebase flows, and a whole-tree diff surface.
- Line-range staging from a visual selection inside the status buffer.
