# 0113 — Tab pages

- Status: **accepted 2026-11-18** (target 0.72); every taste question is taken
  at its recommendation. Neovim behaviour below was measured, not
  remembered (§3).
- Source: the owner — "see if we can / should have tabs in strop? or something
  equivalent, or for them to push back and say no you have enough."
- Builds on [0104](0104-window-tree.md) (the window tree; a tab page is one
  more tree) and [0103](0103-seams-and-splits.md) (who owns a line).
- Amends 0001 §3 ("Tabs are deferred … Revisit only if daily driving begs for
  them"), 0095 §2.7 and §8 (`gt`, `gT`, `ctrl-w T`, `:tabnew`, `:tabnext`,
  `:tabclose` leave the Missing list), 0104 §3 (`ctrl-w c` on a tab's only
  window) and §12 item 4 (`ctrl-w T`).
- Oracle: `nvim 0.9.5 --headless -u NONE` with `set hidden splitbelow
  splitright`. A Python model of §4 was run against it on 3,000 random
  sequences over 27 tab and window commands; tab order, windows per tab, the
  current window of every tab and the current tab agreed in every one.

## Verdict

**Yes to Vim's tab pages, small and exact. No to a buffer line.**

A tab page in Vim is a second window layout over the same buffers. It is not
a list of open files. Those are two different features that share a word, and
the answer differs:

- **A row of open files along the top (VS Code, bufferline.nvim): no.** strop
  has this covered and covered better: `Space b` (buffers, most recent
  first), `:b {name}` with completion, `:bn` / `:bp`, `:ls`, `ctrl-^`,
  `Space f`, the jump list per pane. A buffer line is permanent chrome that
  stops working at ten files, and it is not Vim. Nothing to add here.
- **A second layout (Vim's tab pages): yes.** This is the one thing strop
  cannot do today, and three ordinary situations need it:
  1. *Look at one pane full-screen and come back.* Today the only way is
     `ctrl-w o`, which destroys the layout. Panes are always equal (0104), so
     there is no `ctrl-w |` / `ctrl-w _` either. Vim's answer is `:tab split`
     … `:q`, and it needs tab pages.
  2. *Step aside without tearing down the work layout*: a full-width git
     log, a terminal, a search collection, while three panes of code wait.
  3. *Two tasks in one project*, each with its own splits.

  0001 said a terminal multiplexer covers this. It does not: a second strop
  in another tmux window is another process with other buffers, other undo
  history and other registers, and both write the same session file.

Why now and not "deferred": the cost fell. Since 0104 the layout is a tree
with pure `split` / `remove` / `place`; a tab page is `(tree, panes, current
pane)` and the current one already lives in three `Editor` fields. The whole
feature is one small module, one render row and a set of commands that are
one line each on that module. And the keys are Vim's own (`gt` is on the
Missing list today), so this removes a divergence instead of inventing
something.

What it costs the screen: nothing until a second tab page exists
(`showtabline=1`, Vim's default). With one tab page not one cell changes and
every existing golden stays byte-identical.

## Decisions

1. **Vim's tab pages, Vim's names and keys.** No invented equivalent, no
   leader key, no option.
2. **The tab line shows only with two or more tab pages** (`showtabline=1`),
   on the top row. No setting.
3. **In scope** (all measured against Neovim, §3):

   | Kind | Commands |
   |---|---|
   | Normal | `gt`, `gT`, `{count}gt`, `{count}gT`, `g<Tab>`, `ctrl-w T` |
   | Command line | `:tabnew [file]`, `:tabe[dit] [file]`, `:tabc[lose][!] [N]`, `:tabo[nly][!]`, `:tabn[ext] [N]`, `:tabp[revious] [N]`, `:tabN[ext] [N]`, `:tabfir[st]`, `:tabr[ewind]`, `:tabl[ast]`, `:tabm[ove] [N \| +N \| -N \| $]`, `:tab sp[lit] [file]`, `:tab new` |
   | Changed | `:q` and `ctrl-w q` / `Space w q`, `ctrl-w c`, `:clo[se]` on a tab page's only pane close the tab page when there is another one |

4. **Out, and listed as Missing** (`keymap/missing.rs`): `:tabs`, `:tabdo`,
   `:tabfind`, `:tcd` (0092 pins the project root), `:tab` before any
   command but `split` and `new`, `:{N}tabnew` (position), `:tabnext +N` /
   `-N` / `#`, `:tabclose +N` / `-N` / `$` / `#`, `:tabonly N`, `ctrl-w gt` /
   `ctrl-w gT` / `ctrl-w g<Tab>` / `ctrl-w gf`, `Ctrl-PageDown` /
   `Ctrl-PageUp` / `Ctrl-Tab` (strop has no such keys at all), `strop -p`.
   No mouse (there is none on panes either).
5. **Tab pages are not saved in the session.** The window layout is not
   saved either (0104 §12 item 8); they go together, later. Recorded in 0028.
6. **The current tab page stays where it is**: `Editor.panes`,
   `Editor.layout`, `Editor.active_pane`. The others are parked in
   `Editor.tabs`. Every reader of the visible panes is untouched; the sites
   that follow a *document* (edits, closes, terminal output) also walk the
   parked panes. A parked pane is treated exactly as an inactive pane.
7. **The label is `N name [+k] [●]`**: the tab's number, the file name of
   its current pane, how many more panes it holds, and the unsaved dot if any
   pane in it shows a buffer with unsaved changes. The current label sits on
   the text background, the row on the modeline's; no accent, no new colour.
8. **No kernel change, no new theorem.** The arithmetic is four one-line
   formulas; each is enumerated exhaustively in a unit test and pinned
   against Neovim by the differential corpus (§8.5).

## 1. What strop has today

For many files:

| Need | Today |
|---|---|
| go to an open file | `Space b` (most recent first), `:b {number\|name}` with completion, `:bn` `:bp`, `:ls` (a real buffer) |
| the file I was just in | `ctrl-^`; `ctrl-o` / `ctrl-i` per pane; `Space j` |
| any file in the project | `Space f`; `Space e` (the folder, a real buffer); `Space /` |
| come back tomorrow | the per-project session: buffers, cursors, jump list, command history |

For layouts (`editor/panes/{mod,layout,focus}.rs`, plan 0104):

| Need | Today |
|---|---|
| split | `:sp` `:vs` `:new` `:vnew`, `ctrl-w s v n`, `Space w v -`, `Space t`; they nest |
| move | `ctrl-w h j k l w W p`, `Space w 1`–`9` |
| close | `:q`, `:clo`, `ctrl-w c q`, `:on`, `ctrl-w o` |
| resize, exchange, rotate, move a window | no (panes are always equal) |
| a second layout, or one pane full-screen for a while | **no** |
| the layout in the session | no |

The last three rows are the gap. Resizing was decided against in 0104 and
stays so. This plan closes the middle row.

`keymap/missing.rs` lists `gt gT` ("tab pages"), `ctrl-w T` and `:tabnew
:tabnext :tabclose` as Missing; `docs/editor.md:259` says "Not yet: folds,
tab pages".

## 2. How others do it

- **Neovim / Vim.** Tab pages are layouts. `showtabline=1`: the tab line
  appears with the second tab page. Each label is the window count (if more
  than one), `+` if a window in it is modified, and the name of its current
  window's buffer, the directory shortened to initials
  (` 2 b.txt  + ~/w/s/c/s/s/r/buffer.rs `); an `X` on the right for the
  mouse. Buffers are global; `:b` in any tab page shows any buffer.
- **Helix.** No tab pages. An optional `bufferline` is a row of open files.
- **Zed / VS Code.** Tabs are open files per pane; layouts are not a thing
  you switch between.
- **Kakoune.** None; it sends you to tmux, where each client is at least the
  same server, so buffers are shared. strop has no client/server split, so
  that route is closed (see the verdict).

What fits: Neovim's model and commands, unchanged. The label keeps Neovim's
three facts (name, more windows, modified) in strop's own spelling: a number
first, because `{count}gt` takes one and pane titles already teach "the
number is how you get here"; `●` for unsaved, as everywhere; the name
without initials, because strop never abbreviates a directory to letters.

## 3. Semantics (measured on nvim 0.9.5)

Tab pages are numbered from 1, left to right. "Wraps" means from the last to
the first and back.

| Command | Effect | Current after |
|---|---|---|
| `:tabnew`, `:tabe` | a new tab page **right after the current one**, one pane, a new empty buffer | the new one |
| `:tabnew {file}`, `:tabe {file}` | the same, showing the file (opened as `:e` would) | the new one |
| `:tab sp[lit]` | a new tab page after the current one, one pane, **this buffer with this pane's cursor and scroll** | the new one |
| `:tab sp {file}`, `:tab new` | as `:tabnew {file}`, `:tabnew` | the new one |
| `ctrl-w T` | the current pane leaves its tab page (closed there by 0104's close rule) and becomes the only pane of a new tab page after the current one. With one pane: nothing, `already only one window` | the new one |
| `gt`, `:tabn` | — | the next, wraps |
| `gT`, `:tabp`, `:tabN` | — | the previous, wraps |
| `{N}gt`, `:tabn {N}`, `:{N}tabn` | — | tab page N. No such tab: nothing (`no tab N`) |
| `{N}gT`, `:tabp {N}` | — | N back, wrapping: `(current − N) mod count` |
| `:tabfir`, `:tabr` / `:tabl` | — | the first / the last |
| `g<Tab>` | — | the tab page that was current before this one. If there is none, or it has been closed: nothing, silently |
| `:tabc`, and `:q` `ctrl-w q` `ctrl-w c` `:clo` on the tab's only pane | the tab page goes; its buffers stay open (as Neovim's `hidden`, strop's rule already) | the tab page that takes its number — the one to its right — or the new last |
| `:tabc {N}`, `:{N}tabc` | tab page N goes | unchanged unless N is the current one |
| `:tabc` with one tab page | nothing, `cannot close the last tab` | — |
| `:tabo` | every other tab page goes | this one, panes untouched |
| `:tabm {N}` | the current tab page moves to **after tab page N** (`0`: first) | it keeps the focus |
| `:tabm`, `:tabm $` | to the end | 〃 |
| `:tabm +N` / `-N` | N places right / left; past either end: `no tab there`, nothing moves | 〃 |

Rules that follow from "a tab page is a layout":

- `:on`, `ctrl-w o`, `ctrl-w w`, `Space w 1`–`9`, every split and every
  directional move act inside the current tab page only.
- Each tab page remembers its own current pane; each pane keeps its cursor,
  scroll and jump list while parked.
- Buffers, registers, marks, the alternate file (`ctrl-^`), `Space b`, the
  quickfix list and the project root are editor-wide, as in Vim.
- `!` on `:tabc` and `:tabo` is accepted and changes nothing: no buffer is
  closed, so nothing can be lost.
- `:bd` keeps strop's rule: every pane showing the buffer, **in every tab
  page**, shows the next one instead. (Vim closes those windows, and the tab
  page if it was the only one. strop already differs for windows; this plan
  does not widen or narrow that.)
- With one tab page, `:q` on the last pane closes the buffer and `ctrl-w c`
  refuses, exactly as today.
- A running terminal in a tab page that closes keeps running, hidden
  (`Space b` returns to it), as `:q` does today.
- While the command-line window (`q:`) is open, every command in this plan
  refuses with `close the command-line window first` (Vim's E11).

`:tabm {N}` in code: with the current tab page at index `c` (0-based) of
`count`, valid `N` is `0..=count`; the new index is `N − 1` when `N > c`,
else `N`.

## 4. Data model

New module `crates/strop-engine/src/editor/tabs/{mod,tests}.rs`.

```rust
/// A tab page that is not on screen: its window tree, its panes in
/// reading order, and the pane that has the focus when it comes back.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub(crate) struct TabPage {
    pub layout: Layout,
    pub panes: Vec<Pane>,
    pub active_pane: usize,
    /// The focus epoch when it was left; `g<Tab>` looks for one stamp.
    #[serde(skip)]
    pub left: u64,
}

/// The tab pages other than the current one. The current one is
/// `Editor.{layout, panes, active_pane}`; in tab order it stands at
/// `current`, between `parked[current - 1]` and `parked[current]`.
#[derive(Debug, Clone, Default, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub(crate) struct Tabs {
    parked: Vec<TabPage>,
    current: usize,
    /// The stamp of the tab page left most recently; `None` once it closed.
    #[serde(skip)]
    previous: Option<u64>,
}
```

`Editor` gains one field, `pub(crate) tabs: Tabs`. Nothing else moves.

Invariants (`Editor::tabs_well_formed()`, `debug_assert`ed after every
operation below and at the end of `close_buffer`):

1. `tabs.current <= tabs.parked.len()`;
2. every parked page: `layout.well_formed()`, `layout.leaves() ==
   panes.len()`, `panes` not empty, `active_pane < panes.len()`;
3. every pane of every page names a live document.

`Tabs` methods (pure, no `Editor`): `count()` (`parked.len() + 1`),
`current()`, `panes()` / `panes_mut()` (every parked pane, for the
by-document sites), `take(index) -> TabPage`, `insert(index, page)`.

`Editor` methods (`tabs/mod.rs`), the only code that changes which tab page
is current. Each starts with `cancel_cmdline()` and
`cancel_open(Superseded)`, like `focus_pane`, and ends with
`focus_epoch += 1`, `discover_git()`, `clamp_cursor()`,
`lsp_attach_document(current)` and the invariant assert:

| Method | Does |
|---|---|
| `park() -> TabPage` (private) | `mem::take` of `layout`, `panes`, `active_pane` into a page stamped `left = focus_epoch` |
| `show(page)` (private) | installs a page into the three fields |
| `tab_go(index)` | `index == current`: nothing. Else `previous = Some(stamp)`; `parked.insert(current, park())`; `show(parked.remove(index))`; `current = index`. Insert-then-remove keeps tab order with no index arithmetic |
| `tab_open(pane)` | `parked.insert(current, park())`, `previous` set, `current += 1`, the new page is `Layout::Leaf` + `[pane]`. Used by `:tabnew`, `:tab split`, `ctrl-w T`, `OpenIntent::Tab` |
| `tab_close_current() -> bool` | one tab page: `false`. Else `index = min(current, parked.len() − 1)`; `show(parked.remove(index))`; `current = index`; `previous = None` |
| `tab_close(index)` | the current one: `tab_close_current`. Else remove it from `parked` (its position there is `index`, or `index − 1` past the current); clear `previous` if it carried that stamp; `current −= 1` if it was before |
| `tab_only()` | `parked.clear()`, `current = 0`, `previous = None` |
| `tab_move(index)` | `current = index` (the parked order is already the order of the others) |
| `tab_previous()` | finds the parked page whose `left` is `previous`, `tab_go` to it |
| `tab_step(back, count)` | §3 rows `gt`, `gT`, `{N}gt`, `{N}gT` |

Readers for the renderer and tests: `tab_count()`, `current_tab()`, and
`tab_summary(index) -> TabSummary { document: DocumentId, panes: usize,
unsaved: bool }` (`Copy`; `document` is the page's current pane's).

**Closing as data.** `close_pane_or_buffer` today is two tests in a fixed
order; this adds a third. Compute the owner first (AGENTS.md: typed owners,
not an ordered chain):

```rust
enum Closing { CommandLineWindow, Buffer, Pane, TabPage }
```

`Editor::closing()`: the command-line window's buffer → `CommandLineWindow`;
a commit message → `Buffer`; two or more panes → `Pane`; two or more tab
pages → `TabPage`; else `Buffer`. `close_pane_or_buffer` is a `match` on it.
`ex_close` and `ctrl-w c` refuse only when it is `Buffer`.

**Sites that follow a document** — each also walks `self.tabs.panes_mut()`
(written inline as `self.panes.iter_mut().chain(self.tabs.panes_mut())`, so
the borrow stays per field). Parked panes take the branch inactive panes
take:

| Site | What |
|---|---|
| `document/close.rs` `drop_stale_scratch`, `close_buffer` rebind | panes on the closed document get the next one; when the last document closes, `self.tabs = Tabs::default()` too |
| `transact.rs:183` | selections mapped through the edit |
| `jumps.rs:55` `map_navigation_records` | jump lists mapped |
| `collections/view_positions.rs:94`, `collections/build.rs:382` | selections mapped / reset |
| `collections/loans.rs:73` `release_unheld` | a document a parked pane shows is "shown" and is not released |
| `terminal/lifecycle.rs:268, 313, 347` | `terminal_input` cleared when the job ends; cursors that follow the output |
| `git.rs:402` | the landing cursor of a pane showing the document |
| `session.rs:376` | restore rebinds every pane |
| `trace/generated.rs:125` | every pane's document is observed |

Sites that mean the visible panes stay as they are: `prepare.rs`, `render`,
`panes/focus.rs`, `cmdline/{accept,window}.rs`, `ex/buffers.rs:135`,
`document/snapshot.rs:128`, `completion/context.rs`, `loans::take_shown`,
`transaction_conformance` (its recipes have no tab commands).

**Geometry.** One new function, `Editor::pane_area(geometry) -> CellRect`:
the view, less the top row when `tab_count() > 1`. Its two callers are the
two callers of `Layout::place`: `prepare.rs:185` and `panes/focus.rs`
(`pane_towards` subtracts the same row from its rows). `Layout::place` and
the kernel do not change. `view_stamp` hashes `tab_count()` and
`current_tab()`.

**State.** `state_json` gains `"tabs"` (each tab page's `layout.outline()`,
in order) and `"active_tab"` (0-based, like `active_pane`). The trace seed
(`trace/seed.rs`) and snapshot carry `tabs`; `SEMANTIC_VERSION` 7 → 8, so
older tapes refuse to replay. The seed's validity check runs invariants 1–3.

## 5. The tab line

### 5.1 Rules

1. Row 0 of the screen, only when there are two or more tab pages. The panes
   start on row 1; the pane title rules, the modeline, the echo row and the
   command line are exactly where they are today relative to the panes.
2. The row is `bg.surface` (the modeline's plane): a band above the panes
   and a band below them.
3. Labels run from column 0 with nothing between them. A label is

   ```
   ␠N␠name[␠+k][␠●]␠
   ```

   - `N`: the tab page's number.
   - `name`: the last `/` component of what that tab page's current pane
     shows, as its pane title would name it (`Document::label`): the file
     name, `[scratch]`, `1:fish` for a terminal, `render/` for a folder (the
     slash stays).
   - `+k`: the tab page holds `k` more panes.
   - `●`: a pane in it shows a buffer with unsaved changes.
4. Inks (no new colour, no accent):

   | Cells | Current tab page | Others |
   |---|---|---|
   | background | `bg.base` | `bg.surface` |
   | number, `+k` | `fg.text` | `fg.muted` |
   | name | `fg.text` bold | `fg.muted` bold |
   | `●` | `warning`, as in a pane title | `warning` |
   | `‹` `›` (rule 6) | — | `fg.faint` |

   The current label is the only thing on the row with the text background:
   it reads as the tab the panes below belong to. This is 0103 §4.3: the
   label owns the canvas under it.
5. Nothing on the right. No close mark (no mouse), no clock, no counts.
6. When the labels do not fit (`tabline::fit`, pure):
   1. names are cut to at most `c` cells, `c` from 24 down to 6, the first
      `c` at which every label fits; a cut name ends in `…`;
   2. else every label but the current one drops its name (`␠N[␠+k][␠●]␠`)
      and the current name is cut the same way, 24 down to 6;
   3. else a run of those short labels around the current one: start with
      the current label, add the right neighbour, then the left, in turn,
      while they fit; an end with tab pages beyond it shows `›` or `‹` in
      one cell.

### 5.3 Next to everything else

- **Pane titles.** Unchanged, one row lower when the tab line shows. The
  title rule under the tab line is a rule (`─`); the tab line is a band. They
  do not read as one thing.
- **Modeline and breadcrumb.** Unchanged. The modeline does not say which
  tab page is current; the tab line does, and only when it matters.
- **Echo row, command line, pickers, cards.** Unchanged: they are placed
  from the bottom or the centre of the frame.
- **Folder view, git buffers, collections, help, terminals.** Real buffers
  in panes; they need nothing. `:tab split` on any of them works because it
  is a split.
- **Welcome card.** Shows on an empty scratch buffer, so a bare `:tabnew`
  shows it, as `:enew` does today. Left alone.
- **Small screens.** With two rows the tab line and the modeline are all
  there is; the panes have no cells, as with too many splits today (0104
  §11).
- **Cost.** The row is built per frame only when there are two or more tab
  pages: one `TabSummary` per tab page (no allocation) and the label
  strings, the same order of work as one pane title. No keystroke path
  changes with one tab page.

| `:tab {split\|new}` | open the split in a new tab page; `:tab split` shows this buffer alone |
| `:tabc[lose][!] [N]` | close this tab page, or tab page N; its buffers stay open |
| `:tabo[nly][!]` | close every other tab page |
| `:tabm[ove] [N]` | move this tab page after tab page N (`0` first, `$` or nothing last, `+N` `-N` relative) |

Changed text: `:q` — "close the window; the tab page when it is the last
window in it; the buffer when it is the last window". `:clo[se]` — "close
the window (never the last one)" stays true. `ctrl-w c ctrl-w q ctrl-w o`
keeps its text.

Row order in `tabs.rs` is precedence: `tabnext` (min 4) before `tabnew`
(min 6), so `:tabne` is `:tabnext` as in Vim. Minimums: `tab` 3 (exact),
`tabclose` 4, `tabedit` 4, `tabfirst` 6, `tablast` 4, `tabmove` 4, `tabnext`
4, `tabNext` 4, `tabonly` 4, `tabprevious` 4, `tabrewind` 4. `tab-size`
(min 8) is not reachable from `:tab`.

Missing list (`keymap/missing.rs`): remove `gt`, `gT`, `ctrl-w T`,
`:tabnew`, `:tabnext`, `:tabclose`; add `:tabs`, `:tabdo`, `:tcd` ("list
tab pages, run a command in each, a directory per tab page") under
`Where::Ex`.

## 8. Tests

### 8.1 The model (`tabs/tests.rs`)

- Each row of §3, by name, asserting tab order (documents per tab page),
  the current tab page and the current pane.
- Exhaustive, for 1 to 5 tab pages and every current index: `gt` / `gT`
  inverse of each other; `{N}gt` for `N` in 0..=7; `{N}gT` for `N` in
  1..=7; `:tabm N` for every `N` and `±N`; close of every index. Each
  compared with the formula in §3 written out in the test.
- `g<Tab>`: after `gt`; twice returns; after the previous tab page closed
  (nothing); after `:tabo` (nothing); after `:tabm` (still finds it).
- `ctrl-w T` from a nest: the source tab page's tree is `Layout::remove`'s
  result and its current pane is the one `remove` returned.
- Random walk, plain loops, seeded: 2,000 sequences over the commands of
  §3 plus `ctrl-w s v c o`; `tabs_well_formed` after every step; the total
  number of panes changes only by the command's own amount.
- With one tab page, `:q`, `ctrl-w c`, `:clo`, `:on` behave as before (the
  existing tests, unchanged, are the check).

### 8.2 Parked panes follow their documents (`tabs/tests.rs`)

One test per site in §4's table, each failing without its line:

- an edit in tab 2 above a cursor parked in tab 1 on the same file: back in
  tab 1 the cursor is on the same text;
- `:bd` of a buffer shown only in a parked tab page: that pane shows the
  next buffer; nothing panics on `gt`;
- the first real file replaces the scratch buffer in a parked pane too;
- a collection refreshed while a parked pane shows it; a loaned file shown
  only in a parked pane survives `release_unheld`;
- a terminal whose job ends while parked: on return it is not in TERMINAL
  input;
- a jump list entry in a parked pane moves with an edit;
- seed round trip: capture with three tab pages → restore → equal; a seed
  whose parked pane names a dead document is refused.

### 8.3 Commands (`ex/tests/tabs.rs`, `keymap/tests.rs`)

### 8.5 Differential (`tests/differential/tabs.rs`, prefix `tab/`)

Text `"alpha\nbeta\ngamma\n"`. Every case ends in a tab page showing the
fixture (the harness ends with `:w`), so tab pages are made with `:tab

- Hand cases, named: `:tab split`; `ctrl-w T` from two panes, from one
  (nothing), from the first of three tab pages (lands second); `gt` and
  `gT` wrapping; `2gt`; `2gT` from the first; `g<tab>`, twice, and after
  the previous closed; `:tabclose` in the middle, at the end, at the start;
  `:tabclose 1` from the third; `:q` on a tab page's only pane; `<c-w>c`
  there; `:tabonly` keeping its splits; `:tabmove 0`, `:tabmove`,
  `:tabmove +1`, `:tabmove -1`, `:tabmove 1` from the third; `:only` inside
  a tab page; an edit in one tab page seen from the other (`:tab
  split<cr>dd1gt` — text and cursor compared).
- Generated: `:vs<cr>:tab split<cr>:tab split<cr>` then every three-step
  sequence over `gt`, `gT`, `:tabc<cr>`, `<c-w>T`, `<c-w>v` (125 cases).
- Not in the corpus, with the reason in the file's head comment: bare
  `:tabnew` (no file name to write); **a step that errors anywhere but
  last** — Neovim's `feedkeys` drops the rest of the keys after an error

  generated family cannot hit this before its last step except through

## 9. Not proved, and why

Nothing moves into `strop-kernel`. The decisions here are index formulas on
a list of at most a few entries (`(c + 1) mod n`, `(c − N) mod n`,
`min(c, n − 2)`, `N > c ? N − 1 : N`); §8.1 enumerates every input for up to
five tab pages and the corpus pins them against Neovim. The part that can be
wrong in ways a test will not exhaust — how cells are divided — is already
proved (0104 T1–T4) and is not touched: the tab line only shortens the area
`place` is given.

## 10. Risks

- **A parked pane with a stale document or offset.** The one real hazard.
  Covered by invariant 3 (asserted after every tab command and every buffer
  close), the table in §4 and one test per row (§8.2). A site added later
  that walks `self.panes` by document will miss parked panes: the head
  comment of `tabs/mod.rs` says so, and `Tabs::panes_mut` is the only way
  in.
- **`:q` changes meaning with two tab pages.** It closes the tab page, not
  the buffer. That is Vim, and it is what makes `:tab split` … `:q` work;
  the help text says it.
- **Old tapes.** Refused by the seed version.
- **`g tab` notation.** One new arm in `expand`; the keymap round-trip tests
  (every row dispatches, every row renders) are the check. If the walker
  cannot take a named key after `g` without a wider change, `g<Tab>` moves
  to the Missing list and the rest ships.
- **0112 is rewriting help concurrently.** This plan adds rows to the two
  tables help is generated from and no rendering; rebase on whichever lands
  first.

## 11. Not in this plan

In rough order of value: tab pages and the layout in the session; `:tabs`
(a listing buffer, twenty lines on `open_listing`); `:tab` before `help`
and `terminal`; `:tabdo`; `:{N}tabnew`; `ctrl-w gt` / `gT`; `strop -p`. Not
planned at all: a buffer line, `:tcd`, tab line options, a custom tab line,
a mouse.
